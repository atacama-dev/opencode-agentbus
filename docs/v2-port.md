# OpenCode V2 integration status (public SDK 2.2.7)

**Owner decision, 2026-11-12:** project association is not an authorization boundary. The previous project-move rejection and same-instance placement proof requirements below are historical findings under a now-removed constraint, not release blockers by themselves. Session identity, native approval provenance, cancellation/deletion and correct target routing remain required. Automatic fixed wake is a required feature when enabled, not a permanently omitted part of stock support. See [session identity decision](session-identity-decision.md). Implementation and public-host acceptance of this revision are in progress; earlier tests alone do not establish them.

The V2 server, TUI, and RPC entries are packaged separately; the package root retains the V1 adapter. Dependencies are the published `@opencode/plugin@2.2.7`, `@opencode/client@2.2.7`, and `@opencode/schema@2.2.7`, not a locally staged host package. The default `./server` remains the paired-host adapter and fails closed on stock OpenCode. A **separate, nondefault `./stock-experimental` Effect plugin** probes the public API. Neither entry is certified for stock deployment; do not publish or select either as a supported stock V2 integration yet.

## Exact public host findings and unresolved authority decision

Read published npm tarballs for `@opencode/plugin@2.2.7` (historical `2.0.28` for comparison) and **unmodified `@opencode/core@2.2.7`**, including `dist/promise/adapter.js`, the Effect declarations, `dist/chunks/skill-th2hswax.js` (tool dispatch), `skill-v0cnchkw.js` (permission service), and `skill-w4m28x1c.js` (plugin host), against the [V2 plugin guide](https://opencode.ai/v2/docs/build/plugins/server) and [permissions guide](https://opencode.ai/v2/docs/permissions):

* The stock tool dispatcher constructs `sessionID`, `agent`, `messageID`, and call `id` from the actual request, then passes them to the registered executor. They are **host-provided, not model arguments**. Stock `ctx.permission.assert` is blocking, propagates native `once`/`always`/`reject` semantics, and accepts that host call identity as the source. A blanket claim that public V2 cannot safely deliver messages was too strong.
* Stock permission rules **default allow**. `save` is not an ask. Native configured `agentbus_receive` and `agentbus_search_sessions` policies must resolve to `ask`; configured `deny` is never relaxed. The experimental adapter checks the effective configured agent/session rules immediately before assertion, leaving native saved exact-pair `always` grants to the host. Whether an agent override, concurrent policy change, or other plugin's permission hook can invalidate this guarantee remains for independent review and live tests.
* **Superseded placement design:** the earlier same-instance `session.created` witness, same-project guard, and queued-move invalidation are no longer mailbox authorization checks. The experimental stock adapter now parses the genuine invocation ID, fetches the exact existing session through `ctx.session.get` before broker readiness and before operations, and strictly parses its `ForegroundSessionSchema` projection. Native current session directory is used only when resolving current agent policy; session-ID-directed wake uses no project route. Moves do not deregister the mailbox. A prior test where a queued move preceded approved delivery was a failure under the old design and is **expected delivery** under the owner's new decision when identity and approval remain correct. These changes do not automatically update the separate V1 and paired-host adapters; both retain legacy placement rules and need follow-up.
* **Confirmed stock-host approval mismatch:** in published `@opencode/core@2.2.7`, `skill-v0cnchkw.js` loads/saves native `always` grants with `projectID: location.project.id` (lines near 139 and 285). A deterministic native test with two distinct Git remote-backed project IDs saved `always` for the exact recipient/source pair in one project, moved the same session back to the other project, and observed a **second native prompt for the identical pair resource**. Native configured denies must not be overridden. A safe project-independent grant and revocation design or a host-supported global session-pair approval primitive is still required. The stock adapter must not claim the new cross-project `always` requirement is met merely because a same-project test passes.
* Stock `ctx.tool.list()` returns callable executors to co-resident plugins. Direct calls bypass normal host `execute.before` dispatch. The experimental adapter requires a one-use matching native `execute.before` ticket, but a malicious co-resident plugin that observes the same event may race or steal a ticket. Plugins in the same host have broad authority already; do **not** treat this as a proved isolation boundary. Resolve this threat model with security review or an opaque invocation-bound host primitive.
* Public Promise adapter wraps a rejected Promise executor into `Tool.Error`; a plain native permission reject might become an ordinary tool failure. The experimental adapter instead uses the supported **Effect authoring API** and re-emits the native approval `Exit.cause` after the broker runtime returns. Native decline/correction/interruption still need actual installed-host acceptance.
* The stock adapter now supports explicit `wakeOnMessage: true` through public `ctx.session.synthetic({sessionID,id,text:<fixed literal>,delivery:"queue",resume:true})`, with body-free exact-session native acknowledgement and durable prepared/submitting/admitted/uncertain episodes. It waits for a busy session's execution-end hint rather than interrupting it; retries a genuinely new pending episode after the 30-second cooldown. No public plugin-context inbox reconciliation API is exposed; an ambiguous admission remains uncertain and is never blindly replayed. This can trade liveness for deduplication after a crash. Native queue admission is not model execution. Optional TUI focus remains off. The current background registry opt-in observes same-instance creation events; a historical-session startup snapshot and safely projected project-discovery labels still need design, especially to avoid duplicate wake ownership across plugin instances after a move.

The old adapter retains the reviewed paired-host code behind its capability check and per-invocation assertion. A local TypeScript optional extension declaration applies only to that adapter; the experimental stock entry imports **only public SDK methods**. No peer body is sent to prompts, synthetic admissions, or permission metadata as a workaround.

## Packaging and testing

The package has `./server` (`./v2` alias), `./tui`, `./rpc`, and **nondefault** `./stock-experimental` exports; directory loading uses `server.js`, `tui.js`, and `rpc.js` for the paired adapter only. For an isolated stock experiment, explicitly import the stock subpath through a separate test-only local package entry; there is no default stock directory entry. Options require `experimentalStock: true`, explicit independent `deploymentNamespace`, loopback `endpoint`, `credentialFilePath`, and absolute `brokerDatabasePath`; do not reuse a V1 broker or production state. `wakeOnMessage` may explicitly be true (default remains false); `focusOnReceiveApproval` remains false. The old isolated migration's private paths and acceptance claims are **not** release configuration or QA evidence.

`bun run build`, `bun run test:unit`, `bun run test:integration`, `bun run typecheck`, `bun run lint`, `bun run format-check`, `bun run audit:static`, and `bun run package-smoke` are the repository gates. The package smoke exercises the V1 installed-shape broker flow and both entrypoint shapes; it does **not** establish stock messaging. An isolated published `@opencode/cli-linux-x64@2.2.7` binary (SHA-256 `589253d36810f21217edd51545cd435b328cdc3cf4f451fbe0cce6f88afcf5e1`) loaded an installed-shape **copy** of the built Agent Bus packages under an isolated HOME/config/state, via a test-only entry wrapper; no npm publication or native package install script was used. `packages/plugin/test/stock-wake-host-driver.ts` exercised a deterministic loopback provider, genuine Session/Tool/Permission services, opt-in search/send, **idle recipient autonomously invoking real `agentbus_receive` after fixed queue wake**, native approval pending before body, approved same-session delivery during a queued move, busy recipient queue without interruption, duplicate/rejected-hint coalescing, and a busy recipient completing a real project move before receiving an earlier message. The loopback provider returned only aggregate counters: the fixed wake request had **zero peer-body observations before approval**, while the body and warning appeared in a later tool-result request after approval; the inspected native synthetic item had no description, metadata, project/path or peer data. Interruption and deletion during pending wake produced no approved disclosure or follow-up wake in this bounded run. Its separate real-project native `always` diagnostic returned **UNMET** as above. The earlier `stock-host-driver.ts` covered manual receive/reply and plain/feedback rejection on the previous prototype; that historical run does not certify current source unchanged behavior. Full current-code semantic reply, restart/uncertain episode recovery, saved-grant portability, malicious co-plugin and human UI acceptance remain open. No package publication is authorized by this document.

Wake liveness has a specific unresolved case: a persisted `prepared`, `submitting`, or `uncertain` episode remains held even if the mailbox drains and later refills. Without supported reconciliation, the adapter will not blindly repeat the old wake, but new arrivals can then remain unwoken indefinitely. Focused tests record this conservative current behavior; they do not establish recovery or feature-complete wake reliability.

Dependency audit is not a green gate: the added public SDK tree currently makes `bun audit` report 40 advisories (one critical, 15 high, 22 moderate, two low). Review reachable production paths and obtain upstream fixes before publishing; do not loosen the security boundary or suppress audit findings merely to pass.
